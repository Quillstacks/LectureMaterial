\subchaptergloss{Don't confuse the model with the machine learning system.}
\subsection{The small part and the big picture}

\begin{frame}{Enabling the delivery of the logic}
  \begin{withmargin}
    \begin{tdmain}
      The \alertbf{model} is the small part of a machine learning system. 
      With foundation models and AI engineering, that part got smaller still. 
      The essential work of a machine learning system remains and stacks around business understanding, infrastructure, design pattern and data engineering.
    \end{tdmain}
    \begin{tdmargin}
      Before learning about solving a problem with machine learning, let's first assess when it is actually a good idea to do so.  
    \end{tdmargin}
  \end{withmargin}
\end{frame}

\begin{frame}{(1) Learn}
  \begin{withmargin}
    \begin{tdmain}
        The problem you are solving, requires your system to have the capability to \alertbf{learn}.
        Learning can look different depending on the problem and its context and boundary conditions.
        You already know about supervised learning, unsupervised learning and reinforcement learning paradigms.
    \end{tdmain}
    \begin{tdmargin}
        Machine learning is an approach to (1) learn (2) complex patterns
        from (3) existing data and use these patterns to make (4)
        predictions on (5) unseen data.
    \end{tdmargin}
  \end{withmargin}
\end{frame}

\begin{frame}{(2) Pattern}
    \begin{withmargin}
      \begin{tdmain}
          Learning requires the existence of a \alertbf{pattern}, as opposed to noise or randomness. 
          It is not trivial nor obvious whether there is a pattern in the data, and whether it is learnable.
          Complex pattern is more difficult to embed or state explicitly, this is where machine learning has an edge over classical approaches.
      \end{tdmain}
      \begin{tdmargin}
          Machine learning is an approach to (1) learn (2) complex patterns
          from (3) existing data and use these patterns to make (4)
          predictions on (5) unseen data.
      \end{tdmargin}
    \end{withmargin}
  \end{frame}


  \begin{frame}{(3) Data}
    \begin{withmargin}
      \begin{tdmain}
          Data is available, accessible or acquirable. 
          The data is of \alertbf{sufficient} quality and quantity to support learning, (and to validate for that matter).
          If your approach does not require data, it is because you build on embeddings or foundation models, 
          which themselves are built on data in the first place, or you need to rely on data acquisition and curation as part of your system.
      \end{tdmain}
      \begin{tdmargin}
          Machine learning is an approach to (1) learn (2) complex patterns
          from (3) existing data and use these patterns to make (4)
          predictions on (5) unseen data.
      \end{tdmargin}
    \end{withmargin}
  \end{frame}

  \begin{frame}{(4) Predictions}
    \begin{withmargin}
      \begin{tdmain}
          Machine learning is about making predictions, \alertbf{always}. Predictions can be of different types, such as 
          classification, regression, ranking, clustering, generation and on and on.
          By reframing problems in terms of predictions, we can leverage machine learning to solve them.
          Predictions are approximations by nature and therefore come with uncertainty, 
          which needs to be accounted for.

      \end{tdmain}
      \begin{tdmargin}
          Machine learning is an approach to (1) learn (2) complex patterns
          from (3) existing data and use these patterns to make (4)
          predictions on (5) unseen data.
      \end{tdmargin}
    \end{withmargin}
  \end{frame}

  \begin{frame}{(5) Unseen Data}
    \begin{withmargin}
      \begin{tdmain}
          In a closed system or domain, the data is finite and the system can be fully specified by optimization.
          However, often the domain is open and infinite, and the system needs to be able to \alertbf{generalize} to unseen data.
          Of course, the unseen data is not completely unknown, it is drawn from the same distribution (i.i.d.) as the 
          training data and is thus able to generalize to the unseen data inside a specific domain or distribution.
      \end{tdmain}
      \begin{tdmargin}
          Machine learning is an approach to (1) learn (2) complex patterns
          from (3) existing data and use these patterns to make (4)
          predictions on (5) unseen data.
      \end{tdmargin}
    \end{withmargin}
  \end{frame}


\begin{frame}{Catalysts}
    A catalyst is a substance that increases the rate of reaction without 
    undergoing change itself.
  \begin{columns}[T,onlytextwidth]
    \begin{column}{0.47\textwidth}
      \begin{tdblockt}[equal height group=cat]{The task is repetitive.}
        In a sense that we have a lot of data to learn a pattern from.
      \end{tdblockt}
      \vskip0.5em
      \begin{tdblockt}[equal height group=cat]{The context changes.}
        Meaning that hard coded or other solutions will be brittle and break.
      \end{tdblockt}
    \end{column}
    \begin{column}{0.47\textwidth}
      \begin{tdblockt}[equal height group=cat]{It scales.}
        The need to scale a specific prediction capability, not only a few times.
      \end{tdblockt}
      \vskip0.5em
      \begin{tdblockt}[equal height group=cat]{Being wrong is not too bad.}
        Approximations on unseen data. Failures need to be manageable.  
      \end{tdblockt}
    \end{column}
  \end{columns}
\end{frame}

\begin{frame}{When Not to Use Machine Learning}
  \begin{columns}[T,onlytextwidth]
    \begin{column}{0.31\textwidth}
      \begin{tdblockt}[equal height group=not]{It is unethical.}
        Well, that might also be a general rule. But doing stuff at scale, without human oversight, has its implications.$^*$
      \end{tdblockt}
    \end{column}
    \begin{column}{0.31\textwidth}
      \begin{tdblockt}[equal height group=not]{There's a simple solution.}
        A simple solution, heuristic, or baseline should always be the first step regardless.
      \end{tdblockt}
    \end{column}
    \begin{column}{0.31\textwidth}
      \begin{tdblockt}[equal height group=not]{It's not economically viable.}
        The value of the prediction, needs to be greater than the cost of the system, including development, deployment and maintenance.
      \end{tdblockt}
    \end{column}
  \end{columns}
  \vskip0.8em
  $^*$ More? Enroll to my Philosophy of AI course.
\end{frame}

\begin{frame}{Computational priorities}
  \begin{withmargin}
    \begin{tdmain}
      Research optimises \alertbf{throughput}, production optimises
      \textbf{latency}. 
      \vskip1.0em
      \renewcommand{\arraystretch}{1.3}
      {\centering
        \begin{tabular}{@{}lrr@{}}
          \toprule
          \textbf{Processing} & \textbf{Latency} & \textbf{Throughput}\\
          \midrule
          One query at a time  & 10 ms & 100 queries/s\\
          Batches of 10        & 20 ms & 500 queries/s\\
          Batches of 100       & 50 ms & 2{,}000 queries/s\\
          \bottomrule
        \end{tabular}\par}
      \vskip1.0em
      Every row is the same model on the same hardware. Only the batch changed.
    \end{tdmain}
    \begin{tdmargin}
      Batching waits for the queue to fill, so each single request waits longer
      while the machine as a whole serves far more of them.
      \vskip0.5em
      Batch size is not the only lever. Model size, sample size and how many
      models sit in one request all move the numbers.
    \end{tdmargin}
  \end{withmargin}
\end{frame}


\begin{frame}{Latency is a distribution}
  \begin{withmargin}
    \begin{tdmain}
      Ten requests, latency in ms:
      \vskip0.4em
      10.0,\; 9.7,\; 10.4,\; \alertbf{90.0},\; 9.9,\; 10.0,\; 11.0,\; 9.5,\; 10.2,\; 10.0
      \vskip0.6em
      The mean would be 18.1 ms. Nine of the ten requests were served in about 10 ms. Mean only holds at larger scales.
    \end{tdmain}
    \begin{tdmargin}
  
      \vskip0.5em
      2017, Akamai: A 100 ms delay can cost 7\% of conversions.
      \vskip0.5em
      2019, Booking.com: about 30\% more latency cost about 0.5\% in conversion.
      \vskip0.5em

      three seconds.
    \end{tdmargin}
  \end{withmargin}
  \slidesources{Akamai2017,Booking2019,Google2016}
\end{frame}


% The same ten numbers as the frame before, read the other way: this is the
% copy-then-extend pair, so the sample stays put and only the statistic moves.
\begin{frame}{Percentiles, not averages}
  \begin{withmargin}
    \begin{tdmain}
      The same ten requests, sorted. A percentile is a kind of promise:
      $q$ percent of requests finish in $p_q$ or less.
      \vskip0.8em
      % Same line as the frame before; \pmark (master) hangs a grey label
      % under a value without moving it.
      9.5,\; 9.7,\; 9.9,\; 10.0,\; \pmark{10.0}{$p_{50}$},\; 10.0,\; 10.2,\;
      10.4,\; \pmark{11.0}{$p_{90}$},\; \pmark{\alertbf{90.0}}{$p_{99}$}
      \vskip1.6em
      \vskip0.6em
      \[
        p_q \;=\; \min\Bigl\{\, t \;:\; \frac{\#\,\text{requests} \le t}{n} \;\ge\; \frac{q}{100} \,\Bigr\}
      \]
      The mean of 18.1 ms moves with the outlier, the \alert{percentile makes} the
      outlier visible.
    \end{tdmain}
    \begin{tdmargin}
      With ten requests $p_{99}$ is just the maximum. It takes 100 requests
      before $p_{99}$ and the maximum can differ. Precision needs to be bought with data. 
      \vskip0.5em
      Quality gates count in nines: Three nines is $p_{99.9}$ (1 in 1000
      requests), five nines $p_{99.999}$ (1 in 100000).
    \end{tdmargin}
  \end{withmargin}
  \slidesources{Beyer2016}
\end{frame}

\begin{frame}{Your toxic relationship with mean accuracy}
  \begin{withmargin}
    \begin{tdmain}
      Latency is one metric. It might not be yours to measure. Latency is a distribution. As is any metric. So if you are only 
      reporting mean accuracy, you are \alertbf{underdelivering} already.
      \vskip1.4em
      {\centering
        \begin{tikzpicture}[node distance=9mm]
          \node[tdbox] (q) {Feature};
          \node[tdbox, right=of q] (m) {Metrics};
          \node[tdbox, right=of m] (b) {Methods};
          \draw[tdarr] (q) -- (m);
          \draw[tdarr] (m) -- (b);
        \end{tikzpicture}\par}
    \end{tdmain}
    \begin{tdmargin}
      \vskip0.5em
      Start with the feature the solution has to deliver on. Pick the metrics
      that speak to them. Then curate the data that allows to measure them. Only then build the methods that move those metrics.
    \end{tdmargin}
  \end{withmargin}
  \slidesources{Picard2021}
\end{frame}

% LLM as a judge, taken apart. The bound: a label that is wrong on a fraction
% P of the items can flip at most that fraction of the correct/incorrect
% calls, so measured and true accuracy differ by at most P. The 65% is GPT-4's
% position consistency in Zheng et al. (default prompt, order swapped).
\begin{frame}{LLM as a judge (is the new "I tested on the training data")}
  % Spider-Man pointing at Spider-Man (Spider-Man, 1967, "Double Identity"),
  % via Know Your Meme; full strip width over a blurred copy of itself.
  \sideimagecover[0.33]{spiderman_pointing}
  \sidecaption{The judge meets the judged}
  \titleontop
  \begin{sidebody}
    An LLM judge grades your model with another model. Against its labels
    \alertbf{$\tilde y$} instead of the true $y$, your accuracy is off by as
    much as the judge is wrong.
    \vskip0.5em
    Never for \textbf{validation}. For training data at most, and only while
    it adds no more $\tilde y$ than your ground truth already has.
    \begin{itemize}
      \item \textbf{Hallucination} grades claims it cannot check
      \item \textbf{Position bias} swap the answers, 65\% of verdicts hold
      \item \textbf{Self-preference} rates its own, and its family's, outputs
        higher
    \end{itemize}
  \end{sidebody}
  \slidesources{Zheng2023,Panickssery2024,Li2025}
\end{frame}


\begin{frame}{Perpetuating Bias}
  \begin{withmargin}
    \begin{tdmain}
      Machine learning algorithms do not predict the future, they encode the
      past, and then they act on it.
      \vskip0.5em
      \alertbf{The invisible hand} of performative prediction plays out t scale: With an increase in agentic systems the
      prediction is not merely a reading of the world, it is a push on it.
    \end{tdmain}
    \begin{tdmargin}
      2014 to 2018, Amazon built a r\'esum\'e ranker on ten years of its own
      hiring. It learned to penalise the word ``women's'' and graduates of two
      women's colleges. The project was scrapped.
      \vskip0.5em
      2015, Google Photos labelled two Black users as gorillas. The fix shipped,
      and three years later, was still to delete the label from the vocabulary.
    \end{tdmargin}
  \end{withmargin}
  \slidesources{Dastin2018,Simonite2018,Hardt2022,Perdomo2020}
\end{frame}

\begin{frame}{Why this is different from traditional software engineering}
  \begin{withmargin}
    \begin{tdmain}[0.70]
      Traditional \alert{software engineering} tests and versions code.
      A machine learning system has to test and version code, data,
      and everything the two produce together.
      \vskip0.6em
      \begin{itemize}
        \item How do you version a dataset, and diff two versions of one?
        \item How do you deploy into an environment that keeps moving?
        \item How do you monitor and debug a system with no stack trace?
        \item How do you avoid being harmful at scale and even push it?
      \end{itemize}
